## GetLaunchBootstrapData 接口规格（待服务端实现）
### 目标
鉴权（AuthenticateDevice）拿到 session 后，客户端只发 **1 个 RPC** 取回进入主城所需的全部只读数据，
取代当前的 GetAccount + 批量 Storage 读 + 多个只读 RPC。
### 调用方式
- RPC id：`GetLaunchBootstrapData`
- 入参：无（或 `{ "schemaVersion": 1 }`，服务端按 session.userId 取数）
- 返回：单个 JSON 对象（下表）
### 顶层返回结构
| 字段 | 含义 | 替代的现有接口 | 关键/延迟 |
|---|---|---|---|
| `schemaVersion` | 协议版本号(int) | — | — |
| `account` | 账号快照：`wallet`(JSON字符串)、`inventory`(JSON字符串)、`createTime`、`userId` | Nakama GetAccount | 关键 |
| `serverTime` | 服务器时间(ISO8601) | GetGameTime | 关键 |
| `stamina` | 体力对象 | GetStaminaData | 关键 |
| `storage` | 见下「storage 子结构」 | ReadStorageObjects | 关键+延迟 |
| `equip` | 角色装备 | GetEquipData | 关键 |
| `crystalEquipments` | 水晶装备列表 | GetCrystalEquipments | 关键 |
| `crystalSkins` | 水晶皮肤列表 | GetCrystalSkins | 关键 |
| `playerLevel` | 玩家等级 | GetPlayerLevelData | 关键(可放后台) |
| `shops` | `normal`/`box`/`chapter`/`gem` | GetShopData/GetBoxShop/GetChapterShop/GetGemShop | 延迟 |
| `signIn` | `daily`(reward)、`sevenDay` | GetSignInReward/GetSevenDaySignIn | 延迟 |
| `paymentCards` | `vip`/`monthlyPass`/`sevenDay`/`firstCharge` | CheckVipStatus/GetMonthlyCardStatus/GetSevenDayStatus/GetFirstChargeStatus | 延迟 |
### storage 子结构（按 key 返回原始 JSON 字符串，便于客户端沿用现有反序列化）
关键路径 7 个 key：
`EquipGroup` / `Unlock` / `Home` / `Guide` / `Reconnect` / `User` / `Player`
（对应 NetEquipGroupData / NetUnlockData / NetHomeData / NetGuideData / NetReconnectData / NetUserData / NetPlayerData）
延迟路径 7 个 key：
`Tasks` / `Bag` / `Activity` / `HomeTreasure` / `UnlockMonster` / `SubGame` / `ByteGame`
> 形如：`"storage": { "User": "{...原JSON...}", "Player": "{...}", ... }`，
> 缺失的 key 不返回即可（新号），客户端会走 CreateModel 兜底。
### 硬性要求（务必满足，否则客户端要写大量适配）
1. **子结构原样沿用现有各 RPC 的返回结构**（字段名/类型一致）。
   这样客户端能直接复用现有 `InitModel/InitNormalShopData/...`，改动最小。
2. **每个子模块带独立 `code`**（0=成功），支持 `partial=true`：
   关键模块失败 → 客户端阻塞并提示重试；非关键模块失败 → 降级，不阻塞进游戏。
3. **storage 以 key→JSON 字符串 映射返回**，不要改字段结构（客户端按 StorageAttribute 反序列化）。
4. **account.wallet / account.inventory 原样透传**（当前客户端从 GetAccount 取这两项做钱包/背包）。
5. 只读、幂等，按 userId 批量查库；尽量服务端并行取数，目标 P95 单次往返。
6. 提供 OpenAPI/Proto 契约 + P50/P95 耗时，便于客户端最终确认 Critical/Deferred 划分。
### 客户端对接（接口就绪后）
- `InitData`(关键)：改为调用一次 `GetLaunchBootstrapData`，取 `account/serverTime/stamina/storage(关键7key)/equip/crystal*` 分发到现有 Model。
- `InitDataDeferred`(延迟)：解析 `shops/signIn/paymentCards/storage(延迟7key)`；保留现有逐个 RPC 作为降级路径。
- 可同时取消独立的 `GetAccount/GetGameTime/GetStaminaData` 调用。
